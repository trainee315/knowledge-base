# 实施计划与验收条件

## 1. 统一命令定义

将核心、服务、记录、召回、语义、Agent 和内置插件命令纳入统一注册表。字段定义供帮助和前置校验使用，菜单复用命令行为说明。保留 `org`、`preview` 及旧项目跟踪只读调用的兼容参数。

验收：全部内置插件命令均有帮助；未知命令、未知参数及缺参在业务执行前失败；既有合法脚本通过回归。

## 2. 帮助与错误建议

支持总帮助、组帮助、命令帮助、`-h`、`--help`。提供用途、执行影响、参数、必填关系、示例和常见错误。复杂示例给出 JSON 文件内容。默认 JSON，可显式选择 text。

验收：帮助不读取 input、不等待 stdin、不启动服务；错误含原因、建议及帮助入口；拼写建议不会自动执行。

## 3. 一键启动与诊断

源码入口检查 Node 24+、依赖和构建内容指纹；必要时运行 npm ci/build。服务启动复用现有生命周期，打开浏览器失败不回滚已启动服务。准备日志与服务日志独立。

验收：冷启动、构建复用、源码变化、缺失页面构建、安装失败、构建失败、准备互斥、中文空格路径、重复启动、端口冲突均覆盖；doctor 不创建知识库。

## 4. 常用操作交互

菜单覆盖启动、打开页面、导入、检索后选择资源正文、状态、帮助和停止。路径错误局部重填；`/cancel` 返回，Ctrl+C 退出。已提交的操作等待结果并报告完成变更。

验收：非终端不挂起；参数及业务错误可恢复；资源选择传递正确 ID；取消不产生新的业务操作。

## 5. 集成验证与交付

构建、完整单元回归、独立业务链及项目跟踪测试、启动准备测试、浏览器回归、真实终端帮助及取消验证。发布文档以“候选、待用户验收”记录，正式发布单独进行。
