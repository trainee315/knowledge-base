# v0.0.13 修改计划

状态：P0–P5 实施与验证完成，当前库关键词已重建，2026-11-13 用户验收通过。计划日期：2026-11-12。基线：`21d0de1`，主线包含 v0.0.10、v0.0.11、v0.0.12。实际契约、操作步骤及结果见 [contracts.md](contracts.md)、[running.md](running.md)、[verification.md](verification.md)。

## 1. 目标与范围

关键词页面只展示可搜索、可分页的关键词，不在列表阶段查询关联文档数量。选择关键词后才查询关联文档，展开文档时再读取命中片元及原文位置。同步修改关键词生成与发布流程，再重新生成当前知识库的关键词和索引。

必须保留 Markdown 原件、资源 ID、正文 hash、内容版本、历史正文以及项目和 Session 配置。允许因关键词发布而更新资源元数据 revision 和更新时间；不得把元数据变化计为正文变化。

保留现有标签定义、ID、名称、说明、人工配置及删除抑制状态；更新受新关键词影响的标签浏览聚合和派生关系。本次全量重建固定现有标签集合，暂停自动新增标签，避免关键词重建顺带扩大或清空标签集合。正常后台后续运行仍按既有自动标签策略处理。

本计划最初仅生成文档；随后用户授权实施并在测试后重新生成。下面保留设计与验收条件，实际结果单独记录。

## 2. 已确认的问题与基线

- `src/preview/browse.ts` 的关键词列表先汇总全库词汇，再对每个词重新遍历文档并归一化其关键词，最后才搜索和分页。
- 调查时有 62 篇有效文档、4,049 条文档关键词、3,486 个归一化文档词条；按现有循环结构推算，每次列表请求约执行 1,412 万次关键词归一化。这是静态推算，不是耗时或 CPU 实测。
- `web/src/OrganizationBrowser.vue` 请求每页 30 条，但词表没有独立加载状态；切换时先清空列表，等待期间显示“暂无匹配条目”。
- 关联文档查询先读取全部匹配文档的内容并生成摘要，再分页。
- v0.0.11 已生成 427 个片元；片元词汇比文档前 100 项聚合摘要更完整。此前报告中的片元去重词汇与本节文档词表口径不同，不以两者数量相同作为验收要求。
- 当前关键词元数据版本与 62 篇文档的内容版本匹配。静态调查尚未证明存在独立的“返回成功但应命中的文档为空”缺陷，实施时需要真实页面验证。

## 3. 数据与查询设计

### 3.1 持久词表和双向索引

复用 `cache/semantic/index.sqlite`，按需新增下列结构；最终表名、字段和迁移版本记录在实施时的 `contracts.md`。

- 词表：稳定的关键词 ID、归一化键、展示词形；归一化键唯一。身份不依赖展示词形、排序或当前引用数量。
- 关键词—片元关系：关键词 ID、资源 ID、片元 ID、资源发布版本、原文词形、位置、次数、分数。位置及次数沿用现有提取器契约，不把一个代表位置宣称为全部出现位置。
- 文档发布记录：资源 ID、内容版本、内容 hash、关键词算法版本、模型身份、已发布签名和查询所需的轻量文档信息。
- 关键词索引状态：结构版本、索引发布代次、重建进度、事件消费位置、待处理及失败摘要。

正向索引支持资源或片元查关键词；反向索引支持关键词查资源和片元。两者基于同一份规范关系表建立数据库索引，不维护两份可独立修改的关联数据。关键词—文档关系从命中关系按资源 ID 去重；若后续证据表明需要物化聚合，必须同事务维护并增加一致性检查。

全文词表来自已发布片元关键词的并集。文档元数据仍可保留按权重排序的前 100 项摘要，供旧展示使用，但不得作为完整反向索引的数据源。

### 3.2 列表与关联接口

- 词表默认每页 30 项，服务端设置明确上限。仅返回 ID、展示名称、分页和精简索引状态，不返回逐词文档数量、片元正文或全量任务清单。
- 保留现有关键词名称包含搜索的语义；输入只归一化一次。搜索在词表上执行，可扫描词表，但不扫描文档、片元正文或反复归一化文档关键词。
- 固定按归一化键和稳定 ID 排序。返回索引代次，翻页发现代次变化时明确重置或重试，不能无提示混用不同代次。
- 选中关键词：SQL 筛选关联、按资源去重并分页，再读取当前页的必要文档信息。无关文档和页外正文不进入响应构建。
- 展开文档：按关键词 ID 和资源 ID 查询命中片元，片元同样分页；显示内容版本、行号和原文证据。
- 现有“搜索关联文档标题或摘要”条件必须在分页前应用。使用索引中的轻量投影执行筛选，不能先分页后过滤，也不能为搜索重新读取所有正文。
- 无匹配词条、词条已失效、索引未就绪、正在重建、请求失败分别返回可区分的结果。GET 不启动模型、不隐式重建、不回退到旧的昂贵全库扫描。
- 保留原关键词名称链接的解析兼容，新的页面内部使用稳定 ID。标签和其他组织方式的既有参数及分页语义保持兼容。

### 3.3 缓存与一致性

- SQLite 作为第一层持久派生缓存；首先依靠索引查询消除重复计算，不预先引入整库内存副本。
- 如实测仍需要内存缓存，只缓存有容量上限的词表页、关联文档页等轻量结果。缓存键包含库身份、索引代次、搜索、排序和分页参数；不缓存全部正文，也不单靠 TTL 判断有效性。
- 读请求不得通过每次全量扫描资源元数据来验证索引。利用正式数据 generation、增量事件和持久消费位置检测变化，维护受影响资源的可见状态。
- 若发现尚未同步的正式变更，返回明确的待同步状态或排除已标脏资源，不能把旧内容的关系当作当前结果。事件缺口进入后台核对，不在列表请求内执行全量重建。
- 核心文件事务与 SQLite 事务不能假定为一个原子事务。通过签名、发布记录和可重放任务处理两者之间的中断；发布前重新校验源版本，只公开完整一致的资源代次。
- 单篇资源的片元、关键词关系、已发布签名与索引代次在 SQLite 事务内一起替换；失败保留可恢复状态，不发布半套关系。
- 删除资源时清理其关系并回收无引用词条；恢复后重新排队。多个文档共用的词条不能因其中一篇删除而消失。

## 4. 实施顺序

### P0：冻结契约和失败回归

主要位置：`src/preview/browse.test.ts`、`src/semantic/*.test.ts`、`web/tests`、`tests/semantic`。

1. 补充真实“组织方式 → 关键词”入口的浏览器场景，覆盖列表、点击词条、关联文档和片元；不能用标签内的关键词页代替。
2. 用大于 100 个有效关键词的长文档验证完整索引不会被文档摘要截断。
3. 建立性能结构断言：词表请求不读取正文、不做逐词文档扫描；分页文档查询只获取当前页所需数据。
4. 为延迟响应、错误响应和快速切换建立页面回归，复现误显示空状态及过期响应覆盖风险。
5. 固定关键词 ID、归一化、搜索、分页、索引未就绪和重建状态契约。

完成条件：已确认的问题有修复前失败的回归；成功空结果和请求未完成在测试中明确区分。

### P1：实现索引结构和旧缓存迁移

主要位置：`src/semantic/store.ts`、`src/semantic/types.ts`，新增独立关键词索引模块。

1. 增加词表、关联、发布状态和双向 SQL 索引，并提供集中化读写方法。
2. 实现单资源原子替换、关系删除、无引用词条回收及索引代次更新。
3. 升级语义缓存结构版本；只在维护写路径迁移，读接口不偷偷改库。拒绝未知未来版本。
4. 迁移保留兼容的向量缓存、标签定义、标签匹配及任务状态；现有片元可用于初始回填，但不能把回填标为新算法全量重建已完成。
5. 缺失缓存或恢复后的库明确标为待建；迁移失败可恢复，不清空正式资料。

完成条件：双向查询得到同一关系集合，迁移重复执行安全，失败不会造成部分可见的索引。

### P2：同步改造关键词生成与增量维护

主要位置：`src/semantic/engine.ts`、`src/semantic/keywords.ts`、`src/semantic/source.ts`、`src/semantic/service.ts`、`src/plugins/keywords/index.ts`。

1. 由片元关键词结果生成完整词表和关联，文档前 100 项仅作为兼容摘要写入元数据。
2. 对所有生成入口核对依赖：后台语义任务、显式重试、CLI 提取及旧整理入口，不允许旧处理器覆盖新语义结果或只改元数据不改索引。
3. 分离关键词派生版本、索引发布版本与向量编码身份。本版强制刷新关键词派生及索引；输入和模型身份相同的向量允许复用，不通过重复编码证明“重新生成”。
4. 处理新增、正文更新、删除、恢复、模型或算法版本变化；发布前核验源签名，丢弃过期结果并处理最新任务。
5. 保留持久批次、失败重试、开发负载退让和模型互斥。重复处理无变更文档不写入新代次，不重新计算关键词或匹配。
6. 标签浏览中的关键词聚合改为读取新关系；片元或匹配身份变化时刷新相关派生关系，身份未变时复用有效匹配。

完成条件：任何已发布资源的片元、完整关键词关系和元数据摘要属于同一内容版本；中断恢复不会遗漏或重复关联。

### P3：替换查询链路并保持兼容

主要位置：`src/preview/browse.ts`、`src/preview/readonly.ts`、`src/semantic/api.ts`、`src/semantic/query.ts`，以及必要的服务路由和 CLI 契约。

1. 关键词列表改查词表，移除每词关联文档计数和重复全库归一化。
2. 实现关键词查文档、关键词与文档查片元的分页入口，严格校验关键词 ID、资源 ID、版本及分页参数。
3. 文档标题、摘要搜索与去重先于分页执行；页外正文不参与结果装配。
4. 核对资源组合筛选与关键词 CLI 入口；语义索引就绪时使用完整关系，避免页面能查到而筛选仍受前 100 项限制。保留旧接口形状，必要变化写入契约。
5. 精简返回的状态字段；列表查询不附带全量任务、全部标签或整个片元 payload。

完成条件：列表、文档、片元三个阶段各自只加载所需数据，兼容调用方的结果口径明确且有回归。

### P4：修改关键词浏览页面

主要位置：`web/src/OrganizationBrowser.vue`，必要时拆出关键词专用组件；相关样式及类型定义同步调整。

1. 关键词列表仅展示名称，取消“几篇”和固定“关键词”描述；保留搜索和分页。
2. 初始及切换到关键词页只请求词表，不自动查询所有关键词的关联。
3. 选中词条后分页加载关联文档；展开文档后分页加载命中片元和原文位置。继续支持阅读文档全文。
4. 词表、文档、片元分别设置加载、失败、无结果和待建状态；请求未结束时不显示“暂无匹配”。
5. 使用 AbortController 和请求代次防止旧响应覆盖当前选择；切换关键词、搜索、翻页及卸载时取消旧请求。取消不展示为业务错误。
6. 保留 URL 定位及前进后退；索引代次变化时清理过期分页和选择。未知词条提供重新选择入口。
7. 验证桌面与窄屏，兼容标签、体系、Session 等原有组织页面。

完成条件：实际点击完整链路可用，慢响应有清晰反馈，快速切换不会展示其他词条的文档或原文。

### P5：统一验证并重新生成当前库

1. 完成构建、类型检查、相关核心及浏览器回归；在隔离合成库验证模型及迁移，先修复失败再操作当前库。
2. 建立可恢复的显式重建入口，记录进度、失败、版本、缓存复用及资源计数；不使用无保护的直接删库作为正式重建流程。
3. 重建前记录当前实际有效文档集合、正文及历史 hash、内容版本、项目／Session 配置和标签定义指纹。62 篇仅为调查基线，执行时以当前库为准。
4. 进入维护状态并排空后台写任务，冻结本次文档范围与标签集合；对全部目标文档重新计算关键词派生结果并生成双向索引，复用身份兼容的本地向量缓存。
5. 处理中发生正式内容变更时，将该资源标为待更新并按最新签名补齐，不能静默遗漏。新任务、模型不可用和失败资源均计入未完成状态。
6. 重建采用暂存代次或等效可恢复发布机制；旧结果有明确状态，新代次验收后切换。失败不能展示为全库成功，也不以旧结果冒充新生成结果。
7. 核对正文与配置保持不变、完整双向关系及原文位置正确、任务全部完成；随后恢复既有服务入口并验收真实关键词页面。
8. 保存脱敏验证汇总、命令、规模、性能样本及限制。真实文档和详细词汇证据仅留在被忽略的本地数据目录。

完成条件：当前库重建完成且页面可用；无失败或未处理资源；正文与受保护配置完整；重复运行不重新编码、不重做关键词派生或匹配。

## 5. 验收标准

### 功能和一致性

- 全量关键词列表仅展示词条，搜索和分页稳定，无逐词文档数量。
- 正向关系与反向关系一致；每个关键词可追溯到当前文档版本和原文片元位置。
- 长文档超过摘要 100 项的有效片元关键词仍可被搜索，并能定位关联文档与片元。
- 共用词、大小写、全半角、连续空白及中英文混合词按统一规则去重，展示词形可解释。
- 新增、修改、删除、恢复、失败重试、重建中断及并发源变更均不产生悬空关系、旧版本冒充当前或重复关联。
- 零关键词文档、无命中搜索、失效关键词和索引未就绪分别正确展示。
- 原关键词名称链接、标签浏览和既有组织方式继续可用；现有标签定义保持不变。

### 性能和请求范围

- 用当前规模的合成夹具和至少 500 篇文档、50,000 个词条的合成索引验证查询；该规模不承诺覆盖任意大库。
- 使用 SQL 查询计划及可观测读取计数证明：词表查询不扫描文档正文，不存在“每个关键词再扫描全部文档”的循环；反向查询使用关键词和资源索引。
- 文档结果只装配当前页，片元结果只装配当前页；响应不携带隐藏的全量关系或正文。
- 在同机、同数据、同并发条件下记录改造前后冷／热请求耗时、p50/p95、响应字节和进程 CPU／内存变化。至少各 30 次串行样本及一组连续切换场景，报告方法和局限。
- 初始目标为本机当前库热词表请求 p95 小于 300ms、关键词关联文档与片元单页 p95 小于 500ms；这是待实测的验收目标，不是已有结果。若不满足，先定位并优化，不通过减少词汇或放宽标准掩盖问题。
- 无变更重复生成的编码、关键词派生、关系发布和匹配次数为零；缓存失效后只能返回新代次或明确的待更新状态。

## 6. 交付与实施边界

- 交付源码、数据库迁移、契约说明、操作与恢复说明、测试、当前库重建验证记录。

- 核心属性、复杂存储结构和主要流程添加简短注释；关键常量在所属文件声明用途。
- 本次计划不创建工作树、不修改包版本、不提交或推送、不发布、不调用 PPC。实施结果完成后再同步版本状态和验收记录。
