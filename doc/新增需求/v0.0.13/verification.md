## 性能和边界

性能脚本分别生成当前旧词表规模的合成数据（62 篇、4,049 次文档词汇、3,486 个归一化词）及 500 篇/50,001 个词条的合成持久索引。每个查询单列首次请求，再串行测量 30 次，记录 p50/p95、响应字节、进程 CPU 和采样 RSS。反向 SQL 查询计划命中 keyword_links 主键索引。

当前规模最终复测中，旧词表循环的 p95 为 **1,784ms**，新持久词表为 **23ms**；新文档/片元单页约 13ms/15ms。旧对照复现原循环的内存计算，不包含旧 API 的文件读取成本，因此不是完整 HTTP 端到端对比。

500 篇/50,001 词压力索引的词表、文档、片元查询 p95 分别为 **15.90ms、17.31ms、13.60ms**，均通过目标。SQL 查询计划使用关键词反向索引。

主库恢复服务后另测 30 次 HTTP：词表 p95 **9.75ms**、关联文档 **9.93ms**、片元 **10.62ms**；响应分别约 3.1KB、1.0KB、2.8KB。满足词表 <300ms、文档和片元 <500ms 的本机目标。

“首次请求”未清理 OS 文件缓存；RSS 是同进程采样，不是独立隔离的峰值。合成索引压力测试证明查询规模，不衡量模型质量或保证任意数据量、硬件、并发下的耗时。旧循环和新查询对照均在同一进程内执行，主库 HTTP 测量则包含本地服务。完整样本见性能 JSON，不将摘要数字作为生产 SLA。
