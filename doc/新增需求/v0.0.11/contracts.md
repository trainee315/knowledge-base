# v0.0.11 使用与数据契约

## 页面与命令

“组织与体系 → 标签”提供新增、删除、重新匹配，以及关键词/文档/片元浏览。标签保存后服务自动排队，页面每三秒读取进度。关键词可点击定位相关片元，原文保留版本和行号。资源列表与 `organize query` 的标签筛选使用同一语义匹配关系，支持 any/all 和分页前取交集。

命令入口：`semantic list/get/create/update/delete/retry/retry-all/run`。例如：

```powershell
node dist/cli/main.js semantic create --name 性能优化 --description '游戏渲染和资源加载性能' --json
node dist/cli/main.js semantic list --json
node dist/cli/main.js semantic get --id 标签UUID --view fragments --json
node dist/cli/main.js semantic retry --id 标签UUID --json
```

复用 `recall model prepare` 准备的本机模型；没有模型时明确显示等待/失败，不下载模型，也不调用生成 API。计算遵守现有开发负载保护和跨进程模型互斥。旧库没有模型且未使用语义入口时，保持原只读行为。启用语义整理后，旧 organizer 自动候选评分停止，`organize run` 转交语义处理；旧显式关系评分及历史归属数据仍保留。

## 生成与匹配

- 关键词是原文连续切片，包含位置、次数和分数。中文按词、英文实体允许完整短语，禁止跨段拼接；以向量代表性和多样性筛选。每片元最多 48 个候选、12 个结果，文档汇总最多 100 项。当前为轻量规则候选，不保证识别所有专有名词。
- 标签自动名称来自至少两篇文档的前两项代表关键词，每轮最多晋升 4 项；归一化名称/别名去重，并对很相近的已有概念进行保守复用。不会生成关键词之外的上位概念。
- 人工标签使用名称、别名和说明构造检索向量。相似度达到 0.55 的片元进入浏览结果，结果按分数排序。分数表示向量相关性，不是概率。
- 文档按最高片元分数排序并去重；关键词在命中片元中汇总，按片元相关度与关键词代表性排序。可能包含误匹配，暂不引入逐文档裁决。

## 更新与恢复

正式标签继续存为核心 `tag` 组织。删除写入 `semanticDeletedAt` 墓碑并隐藏入口，不破坏原文、关键词或历史引用；墓碑抑制自动同名重建。人工显式创建同名标签可恢复原 ID。新浏览不把旧人工接受/拒绝作为强制过滤条件，旧记录仍可读取。

片元、任务、向量、关键词派生和稀疏命中存于 `cache/semantic/index.sqlite`，可重建。编码身份为模型指纹、用途（query/document）与实际文本；片元编码包含标题、章节和正文，兼容读取已有召回向量缓存。片元 ID/位置变化不会阻止相同编码内容复用。

资源修改只替换该资源的片元及匹配；标签含义修改只刷新该标签。标签和资源的目标指纹分别包含算法版本。每 16 条文本保存一批编码，每 128 个片元保存标签匹配进度；任务跨重启续跑。连续变更合并为最新目标，正式写锁内重新核验版本后发布。旧版本、已删除资源和已删除标签不作为当前结果返回。

服务每秒检查待执行时间，正常每 30 秒核对漏事件；写操作主动唤醒。忙碌/开发负载退让后短暂重试，普通失败 60 秒后重试，也可人工立即重试。备份/恢复和停止服务前排空后台，派生缓存不进入正式备份，恢复后按正式原文和标签重建。

开启正文、关键词、标签插件是处理前提；禁止覆盖未来版本关键词 meta。没有变更时不重新编码或计算相似度；核对仍需要扫描资源/标签元数据。当前匹配使用现有 SQLite 存储和向量点积，尚未引入近似最近邻索引。

## 验证入口

- `npm test`：完整构建与回归。
- `npm run test:semantic`：增量、出处、删除、重试、版本、HTTP及组合查询专项。
- 设置 `KB_SEMANTIC_MODEL_DIR` 指向已有本地召回模型缓存后，执行 `node tests/semantic/live.mjs`。仅复制模型到隔离测试库，资料全部为合成文本。
- 执行 `node tests/semantic/browser.mjs` 验证上一项生成的隔离资料库，输出桌面/窄屏截图；本地资料路径仅写入被忽略的 `.runtime/v0011-live.json`。
