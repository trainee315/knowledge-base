# v0.0.15 公共契约

## 关键词

关键词来自原文连续切片，保存内容版本、片元、起止偏移、代表位置计数、语义分数及来源 `explicit / heading / code / body`。显式关键词、完整标题概念与代码标识符优先；普通正文候选经过完整性、泛词、模板、文件碎片和标识符边界检查。不补足固定数量，允许无有效关键词。

保留持久词表与关键词—文档—片元双向查询；文档元数据前 100 项仍仅作摘要。关键词算法身份不一致时只读接口返回待更新，不以旧词表冒充新算法结果。读取不触发模型或磁盘迁移。

## 标签与候选

`semantic create/update` 支持 `aliases` 字符串数组，最多 20 项；名称及单个别名最长 100 字符，含义说明最长 1,000 字符。名称和别名共享归一化唯一命名空间；空值、重复及跨标签冲突报错。编辑自动标签会标记为人工维护，名称、别名和说明变化只重排受影响标签。

标签名称及别名分别编码，说明提供上下文。明确正文术语、别名或文档主题形成可解释证据；纯语义匹配采用独立门槛。候选与正式命中分别保存，不直接相加不同评分体系，也不把相似度显示成概率。

- `view=documents`：正式相关文档，按资源去重；`fragments` 只统计正文证据数，主题依据可为零。代表片元优先使用正文依据。
- `view=fragments`：正式正文命中，排除只有标题或显式主题字段的结果。
- `view=keywords`：正式正文命中片元中的关键词，继续支持按词定位。
- `view=candidates`：待核对的片元；不进入正式标签计数或资源组合筛选。

结果的 `evidence` 包含 `kind`、`term`、`scope`、`similarity`、`ruleVersion` 及存在时的 `start/end`。`kind` 为 `body-term / alias / title / explicit / semantic`；`scope` 为 `body / document`。标题若来自文件名，不伪造正文位置。范围排除、示例、词条列举等提及应区别于实质讨论。

页面支持别名与含义编辑、正式结果与候选切换，以及原文定位；旧标签 CRUD、分页、URL 定位与 CLI 默认 JSON 输出继续可用。

## 自动标签及存储

自动标签综合原文标签字段、显式关键词、文档标题及跨文档支持，优先完整具体概念；普通两字泛词、版本残片和模板套话不因频繁出现就晋升。名称归一化去重，不按高向量相似度强行合并不同概念。新名称来自文档证据，不继承已丢弃的旧组织定义；文档中本身存在的旧名称仍可能被合理重新提取。

语义 SQLite 升级至 schema 3，增加 `match_evidence` 表。既有 `matches` 仅保存正式匹配，旧调用方不读到候选。v1/v2 缓存只在写入时迁移，输入相同且模型身份兼容的向量可复用；未来未知 schema 拒绝访问。关键词及匹配规则均纳入派生身份，更新规则后重新计算旧未命中结果。

本版沿用本地编码模型。重排模型实测未稳定改善短标签判断，不默认启用；显式比较工具为 `tests/semantic/reranker-evaluate.mjs`。
