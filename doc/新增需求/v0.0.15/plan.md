# v0.0.15 修改计划与验收标准

状态：实施完成，五轮优化及当前库重建验证通过，2026-11-13 用户验收通过。计划日期：2026-11-13。调查依据见 [需求说明](readme.md)，实际结果见 [验证记录](verification.md)。

执行修订：用户已明确授权丢弃全部旧标签和关键词数据，完整保留文档。下文保留人工标签与旧决定、清理需预览的原始设计，在本次当前库重建时被该授权覆盖；其他数据保留及质量标准继续适用。关键词提取、标签匹配与自动生成、独立质量评估并行；主任务负责接口、页面、清理重建与最终集成。新结果须经实际检查、继续优化和重新验证后才交用户验收。

## 一、设计原则

- 关键词应表达独立概念；向量相似度用于排序，不能替代词语完整性判断。不以生成数量多作为质量目标，不强行填满每片元名额。
- 标签分别保存名称、别名和含义说明。词面与别名命中提供可解释证据，语义召回补充不同表达；含义说明用于消歧，不视为一组同义词。
- 文档主题相关与片元正文相关分别判断。标题命中可支持文档归类，但不能据此将该文档的全部片元标为正文命中。
- 强证据结果进入正式匹配；证据不足的内容仅进入独立候选视图，不计入正式标签数量和资源筛选。分数不显示成概率或准确率。
- 保留原文、资源 ID、正文 hash、内容版本、历史、项目和 Session 配置；保留人工标签定义、人工决定及删除抑制状态。

## 二、实施顺序

### P0：冻结问题样本与基线

1. 记录实现开始时的代码状态、库范围、模型身份、关键词与匹配版本；保留现有未提交改动。
2. 在隔离数据副本中建立质量样本：残句、完整技术词、版本与代码标识符、重复模板、中文与英文别名、宽泛标签、多主题文档。
3. 固定关键正例：事件中心文档与其契约正文、8 篇标题含 Prefab 的相关文档；逐篇标注相关性，不能将全部 18 篇提及 Prefab 的文档自动当作正例。
4. 固定关键反例：PNG 压缩排查对事件标签的误命中、来源追溯段冒充业务正文，以及偶然提及但不以该概念为主题的段落。
5. 将调参集与独立验收集分开；锁定标注和抽样规则后再调整算法，避免仅针对这两个标签写特例。

交付：本地样本清单、原始结果与评分基线；仓库保存脱敏测试夹具和评价方法。

### P1：关键词候选与排序改造

主要位置：`src/semantic/keywords.ts`、`src/semantic/types.ts`、`src/semantic/engine.ts`。

1. 提取原文显式关键词、标题术语、正文候选及代码标识符，保留来源类型和原文位置；显式关键词也通过质量检查。
2. 保留中文分词能力，增加术语和短语完整性约束；去掉“含空格优先”的普遍排序规则，避免任意相邻分词拼接成为最终候选。
3. 过滤悬空虚词、未完成动作描述和版本号拼接残句。完整版本标识、产品名、命令与 API 名称可保留，不简单删除所有数字、英文或动词。
4. 对来源追溯、重复免责声明、流水记录和路径列表降权；正文中有实质意义的同名术语不因出现在模板中而全局禁用。
5. 综合完整性、标题及显式字段支持、正文支持、语义相关性和冗余度排序；控制包含关系重复，允许输出少量关键词或零关键词。
6. 复用现有持久词表和双向索引。展示词条继续有真实原文证据；同义概念归一与别名映射不能伪造不存在于原文的偏移。

完成条件：已确认残句不再入选；完整技术词仍可检索；原文位置与当前内容版本一致。

### P2：标签混合匹配与证据定位

主要位置：`src/semantic/source.ts`、`src/semantic/engine.ts`、`src/semantic/vectors.ts`、`src/semantic/types.ts`。

1. 分别处理名称、各个别名和说明；对标题、章节、显式关键词与正文做规范化词面匹配，并结合局部上下文。英文匹配处理大小写、标识符边界，避免无条件子串命中。
2. 提供可维护的通用别名机制，以“预制体 / Prefab”验收；不在匹配器中硬编码这两个标签的专用分支。自动建议的别名可查看、修改或拒绝。
3. 语义召回用于补充候选；对有限候选评估现有本地重排能力。是否启用重排由独立样本质量和耗时决定，所有模型计算在后台完成。
4. 对短标签和宽泛标签结合含义说明与上下文消歧；阈值通过样本校准，不把统一降到 0.40 作为解决方案，也不直接混加不可比的词面、向量和重排分数。
5. 分开保存文档主题依据与片元正文依据。选择代表片元时优先实质讨论，来源追溯和模板段不能仅凭重复标题成为主要证据。
6. 新增标签与资源更新走同一匹配规则，结果记录依据类型、命中词或别名、原文位置及算法身份。

完成条件：明确相关文档可命中，误匹配得到约束，用户能从正文解释每个正式结果。

### P3：接口、页面与自动标签治理

主要位置：`src/semantic/api.ts`、`src/semantic/store.ts`、`src/semantic/engine.ts`、`web/src/SemanticTags.vue`，以及受影响的 CLI 契约与帮助。

1. 标签页面支持新增和编辑别名、含义说明；说明修改后重跑受影响标签，刷新结果状态。
2. 文档及片元结果展示“标题术语”“别名命中”“正文语义”等依据和原文；文档主题结果不伪装成全部正文片元命中。
3. 正式匹配与低置信度候选分开展示、计数和筛选；零命中、处理中、失败分别可见，不向普通页面暴露调参细节。
4. 自动标签沿用跨文档支持，同时增加概念完整性、正文支持、模板排除和重复概念检查；不把跨文档出现本身视为标签质量证明。
5. 对已有低质量自动标签生成清理预览，包含原因、来源、引用和影响；不按旧词条消失直接删除标签。执行清理由后续明确指令确定，复用既有删除抑制机制；人工标签不自动合并或删除。
6. 保持关键词按需分页、标签组合查询、URL 定位和 CLI 默认 JSON 行为；新增证据字段与数据库迁移记录到实施时的公共契约。

完成条件：页面能配置、解释和复查匹配；新噪声不会继续自动晋升；旧数据处置可审阅。

### P4：版本失效、重建与恢复

1. 升级关键词派生版本及匹配规则版本；规则、别名、说明、编码输入与模型身份纳入相应签名。
2. 关键词规则变化仅复用身份兼容的编码缓存；匹配规则变化强制刷新旧命中和旧未命中判断，禁止把旧匹配缺失继续当作零分复用。
3. 如增加证据字段或表，提供缓存结构迁移；读请求不运行模型、不隐式重建，也不把旧规则结果冒充新结果。
4. 在隔离副本完成新旧结果对照、版本迁移及中断恢复；通过后，在后续实施授权范围内使用正式重建入口处理当前库。
5. 重建前记录正文、历史、配置和标签定义指纹，固定本次范围，暂停自动新增标签；使用暂存代次或等效恢复机制发布，避免半套关系可见。
6. 处理中发生正文或标签变更时按最新签名补齐；记录任务进度、失败和重试，支持重启续跑。
7. 验证受保护数据一致、关键词双向关系与标签证据一致、所有目标任务完成后恢复正常后台。已有自动标签清理与索引重建分开执行。

完成条件：当前库结果属于新算法版本，失败可恢复，无悬空关系或旧结果误报；无变更再次运行不重复编码和派生。

### P5：回归与交付

运行构建、类型检查、相关单元与集成测试，以及关键词和标签页面回归。模型质量必须使用现有真实本地模型验证，不能只用固定向量测试替代。按下述标准记录结果，再交用户验收。

交付源码与迁移、公共契约、运行和恢复说明、质量对照及性能记录。实现完成后才更新包版本和实际状态，验收与正式发布另行记录。

## 三、验收标准

### 关键词质量

- 固定负例“0.0.10 改动仍未”“0.0.10 修改不要”“以所列证据”“执行建议不”不再出现；同类未参与调参的残句也纳入抽查。
- 固定正例中的技术词、API、命令、版本实体仍有合理保留；不能通过清空结果或仅保留少量通用词通过验收。
- 对不少于 100 个分层抽样词条标注“完整且有检索价值 / 无效残片 / 存疑”，覆盖中文、英文、混合词、长文与模板密集文档；目标有效比例至少 90%，存疑不计有效。记录样本和分母，不宣称为全库准确率。
- 另设原文关键概念正例清单，保留率目标至少 90%，与有效比例共同验收；缺失项逐项列出。
- 原文偏移、内容版本及正反向关系校验全部通过。

### 标签与证据质量

- “事件”命中事件中心专门文档，主要证据定位到契约、订阅、派发或生命周期正文；PNG 压缩负例不进入正式匹配。
- “预制体”在配置 Prefab 等价别名后，命中经标注确认的 8 篇标题相关文档；含义说明参与消歧，而非要求用户自行反复猜测阈值。
- 对名称相同但说明不同、仅正文命中、仅标题命中、别名命中、语义同义但无词面重合的情况提供独立回归。
- 在预先标注的独立标签—文档样本上，正式匹配精确率与召回率目标均至少 90%；展示 TP/FP/FN、样本范围及失败案例，不将候选结果计入正式命中。
- 自动标签固定负例不再新增；既有人工标签、人工决定与删除抑制记录保持完整。

### 一致性、体验与性能

- 覆盖新增、修改、删除、恢复、别名及说明变更、算法升级、并发源变更、失败重试和重启续跑。
- 关键词词表仍按持久索引分页；页面读取不触发模型，关联结果按需加载，切换或翻页不会展示旧选择的结果。
- 同机同数据记录改造前后后台耗时、编码和比较数量、缓存命中、内存，以及至少 30 次页面请求的 p50/p95；明显退化必须解释并解决，不能用减少正例覆盖掩盖。
- 桌面与窄屏完成标签配置、查看依据、候选切换、关键词查文档查片元的实际交互验证。

以上质量比例是本版待验证目标，尚非已实现结果。阈值与评分参数由开发集校准；独立验收失败时修复算法，不事后删样本或放宽目标。
