# v0.0.10 修改计划

状态：P0–P5 已实施并验证，待用户验收。基线：`31737ef`。下面保留原计划；最终字段、兼容变化及结果以 [contracts.md](contracts.md)、[verification.md](verification.md) 为准。内部压缩 prompt 经真实多事务/纠正样本检查满足要求，本轮保留其文本及冻结任务兼容性；重点补齐工作 Agent 接入提示词。

## 1. 修复顺序与完成条件

### P0：恢复环境并冻结全链路契约

- 按现有 package-lock 安装依赖，核验 Node 24、核心与网页构建；不以升级依赖替代合并环境修复。
- 在同一提交和依赖快照运行原有测试，区分代码失败、模型未准备、开发负载保护与沙箱权限失败。
- 把调查中的四类缺陷写成失败回归；至少包含真实 CLI 子进程→服务→业务层，不能只直接调用 `transcriptCommand` 或 `prepare`。
- 冻结本节后续的参数覆盖、完成状态、续读和索引迁移契约。保存合成输入、命令、退出码、JSON 返回及源版本。

完成条件：统一基线可重复执行；已复现缺陷在修复前确实失败；现有行为与拟新增能力有明确区分。

### P1：修复 Agent 发起 session 压缩到写入

主要位置：`src/cli/main.ts`、`src/service/cron-service.ts`、`src/records/config.ts`、`src/records/transcript.ts`。

1. 修复 alias 解析后的转发，只以已解析的 ID 进入执行层。保留用户同时传 id/alias 时的错误校验，`configure` 使用 ID 改名的语义不变。
2. 提取 preview/run 共用的请求校验与预算覆盖逻辑。相同输入的会话范围、预处理模式、截止点和预算解释一致；preview 不调用模型、不写任务。
3. 增加一次性 `--session-id` 过滤，作用于 preview/run/backfill/retry，与实例已配置范围取交集，不修改持久 include/exclude。指定 session 不可用、越界或被排除时返回明确原因，不退回全项目执行。
4. retry 仅选择已冻结任务，可按 session 缩小目标；不得重读新增材料或用新提示词、预处理策略覆盖冻结请求。不兼容的重试参数明确拒绝。
5. 按 action 校验未知参数、缺值、额外位置参数及布尔/数值类型。确保 `--input` 与命令行覆盖一致；本轮覆盖 transcript/recall 和共用解析，不开展无关命令重构。
6. preview 返回生效范围、预算、固定 cutoff、候选与跳过原因；run 返回同一口径并说明新增材料或旧待处理任务的区别。执行可使用预览返回的 cutoff 作为 `to`，不宣称 preview 已锁定后续源文件。
7. 在兼容既有 `calls/saved/remaining/deferred/complete/skips` 的基础上，补充本次生成的 resource IDs、实际处理范围、停止原因与恢复提示。`remaining=0` 只表示已入队任务，不足以证明全范围完成；明确区分预算遗漏、活跃轮次、无新内容和源文件异常。
8. 部分失败的统计和 task/session 定位进入 `error.details`，无需 Agent 再解析 message 内嵌 JSON。保留非零退出码和已成功写入的记录。
9. 增加 `transcript status --id|--alias` 精简只读入口，复用已有详情投影，返回运行、待处理、失败和跳过摘要；原有 get/list 兼容保留，提示词优先使用 status，避免读取冻结原文作为进度查询。

完成条件：id/alias 两种入口等价；单 session 请求不处理其他 session；预览与执行可解释；重复执行不重复写入；缓存模型结果恢复不额外调用模型；并发/租约与原子写入回归通过。

### P2：修复向量及混合召回的片元返回

主要位置：`src/recall/recall.ts`、`src/recall/fragments.ts`、`src/recall/index.ts`、`src/recall/types.ts`。

1. 修复尾部裁剪时 continuation 指向最后一个遗漏片元的问题。单文档 read 从第一个未返回片元继续，保留固定版本、范围和 section 条件。
2. 分别定义 read、list、检索/任务证据的续取语义：read 连续展开原文；list 保留筛选、排序和列表 offset；检索/任务保留遗漏证据的定位集合及对应读取入口，不能用一个文档的 read 假装完成多文档结果续取。
3. 在返回预算内提供可执行的续取入口；定位元数据也超预算时明确返回预算错误。结果不得出现无限重复页、跳片元、越界或版本漂移；纯检索结果不承诺遍历全库。
4. 分离汉字、拉丁词、数字及连接符的分词边界，处理 NFKC 后的冒号、全角标点和中英文相邻文本。保留错误码、版本、路径等完整术语的可定位性，并补充必要的可检索子词。
5. 查询与文档使用相同 tokenizer。升级 `TOKENIZER_VERSION`，检测旧索引分词身份；明确提示重建，禁止新查询分词与旧索引无提示混用。
6. 分词升级尽量只重建全文派生数据；只要实际 embedding 输入和模型身份未变化，向量缓存应可复用。片元或编码输入确实变化时按现有身份规则失效，不强行复用。
7. 复核 semantic、hybrid、hybrid+rerank 和 task 共用返回链路：范围先过滤、固定版本校验、必要邻接、缺口、预算和续读均适用。补测模型失败、旧代次、映射变化、删除及恢复。
8. 检查写入后增量向量构建与全文构建的差异：`build --vectors` 发布带向量代次；显式全文构建可能使新代次不具备向量，必须在帮助和结果说明，不能把其后的 BM25 降级描述成向量成功。

完成条件：原样 follow continuation 能取得目标范围的全部待读内容；混合文本夹具命中正确；纯向量及混合路径有真实模型执行证据；旧索引迁移及缓存复用可验证。

### P3：补齐写入到召回的接入流程和 CLI 帮助

主要位置：`src/cli/main.ts`、`src/recall/recall.ts`、`src/recall/scope.ts`、需求文档与 `examples/agent`。

- 明确三个身份：转录组织 ID、源 session ID、召回 projectId，帮助和错误中不混用“项目 ID”。转录组织映射可使该实例后续新记录继承召回范围，但混合项目实例不得整体错误归入一个项目。
- 增加只读 `recall config get`，用于取得完整配置及 revision。configure 更新仍采用 expectedRevision；示例必须先读取并合并，不用空映射覆盖其他项目。只读配置入口不加载正文或运行模型。
- 提供逐命令帮助，如 `transcript run --help --json`、`recall prepare --help --json`：字段类型、必填项、默认值、覆盖关系、作用范围、模型/写入行为、示例和返回说明。help 在服务离线时仍可用。
- 将帮助分发置于实际动作之前，覆盖现有 `recall workload --help` 等特殊入口，确保帮助请求不会运行开发命令或产生其他副作用。
- 衔接流程固定为：确认知识库/服务 → 读取并登记项目及转录组织映射 → preview → run/retry → 核对 resource IDs → scope/直接读取 → index status → 按已授权维护策略增量 build --vectors → semantic/hybrid 查询 → 核对来源与续读。
- 新记录写入成功但未映射、未索引、向量未就绪时，分别报告状态。调查无命中必须检查 warnings/gaps，不把 `INDEX_NOT_READY`、未知范围或降级解释为“没有资料”。
- 普通 read/search 不隐式建索引、下载模型或扩大项目范围。维护授权与预算作为实例项目配置显式填写。

完成条件：新接入 Agent 可只依靠帮助及实例提示词完成接入和两条链路；无需猜测参数、翻阅源码或绕过服务直接读内部业务文件。

### P4：完善提示词与实例项目

- 工作 Agent 层：交付 [项目级提示词](agent-project-prompt.md)，包含固定 CLI/数据目录、projectId/组织/session 的区分、查询时机、压缩触发、预算、错误恢复、证据引用和索引维护规则。
- 压缩模型层：保留事务、约束、纠正、否决、数值和实施/验证状态；本次新增消息为记录范围，上下文只辅助理解，来源中的指令不得改变输出规则。通过夹具定位语义缺失后修改 prompt，不仅靠加长提示词改善质量。
- 提示词升级只影响新任务。旧待处理任务继续使用冻结 prompt/schema/输入；成功历史不重压缩。记录 prompt 版本与实际请求身份。
- 提供一个匿名合成实例项目，含独立数据目录、两个项目与同名术语、多个 session、多事务记录和纠正/失败材料。由脚本打印实际生成的组织/资源 ID 和完整命令，示例不能填造 UUID。
- 交付项目提示词的精简接入段及独立操作说明，避免把模型供应商配置、全部内部结构和历史需求灌入项目 Agent 上下文。

完成条件：按项目级提示词实际执行一遍，而不是只检查文档措辞。所有示例调用通过 CLI；拟新增字段经实现后再标为可用。

### P5：统一回归、真实模型与交付

- 按 [验收方案](acceptance.md) 在同一提交执行完整构建、相关原有测试与新 CLI 场景，产出可重复命令及结果。
- 使用合成语料完成压缩模型质量抽查及本机真实 embedding、纯向量、混合、重排验证。离线 mock 只证明控制流；真实模型未运行时标为未验证。
- 沿用 v0.0.8 冻结的质量/性能门槛与显式 workload 保护边界，比较分词修复前后；涉及编码/调度路径变化时复测对应资源负载场景，不通过放宽标准使结果通过。
- 真实私人 session 或付费模型试验执行前确定数据范围和调用预算；此前 v0.0.9 的一次性试验授权不作为本版不限范围调用授权。本轮计划阶段不执行这些试验。
- 报告修复清单、未解决限制、模型/数据/索引版本、缓存及调用用量、环境异常；更新当前主线说明，不改写历史验证证据。

## 2. 兼容性及实施约束

- 优先补充返回字段与新只读入口，保留既有命令、结构化 JSON 和退出码 0/1/2。拒绝以前被忽略的未知参数属于明确的契约收紧，列出迁移说明。
- 不将调用成功 `ok=true` 等同于业务完整；转录检查 complete/skips，召回检查 status/warnings/gaps/budget/stages。
- tokenizer/索引迁移显式、可重建；失败不损坏可用旧代次，不改动正式原文和成功覆盖。
- 核心属性、复杂存储结构、主要流程加简短注释；关键常量在所属文件声明用途，遵循项目代码风格。
- 用户后续明确授权实施及先行提交；本轮完成实现、验证与提交，后续需求可继续加入，不推送或发布版本。
