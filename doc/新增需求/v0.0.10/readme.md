## 目标

1. Agent 发起指定 session 的压缩请求，经预处理、冻结请求、生成、校验、写入后，可以判断本次结果、未完成范围与恢复方式。
2. Agent 发起项目范围内的调查请求，经向量/混合检索、片元组装和续读后，可以得到完整、可定位的证据，准确识别缺口及降级。
3. 压缩产物能够通过显式项目映射与索引维护进入召回；验证写入、索引可见、实际命中这三个不同状态。
4. CLI、帮助、输入示例、项目级提示词使用一致的参数与返回契约。

## 调查依据

- 已复现：`transcript run/retry/backfill --alias` 在服务解析 ID 后仍携带 alias，触发二选一校验并退出 2。
- 已复现：两个 session 的配置传 `preview --max-sessions 1` 仍返回两个候选；未知 `--session-id` 静默忽略。
- 已复现：六个片元设置 `maxFragments=1`，返回第 0 个后续读指向第 5 个，漏读第 1–4 个。
- 已复现：`CHAIN_PROBE_8192：限制为8` 被分为整体 token `chain_probe_8192:限制为8`，按标识符或“限制”查询均漏命中。
- 已确认的衔接要求：转录 `projectDir` 不等于召回项目映射；登记转录组织映射后，范围内记录由 0 变为 1。新记录还需要显式索引构建才进入检索。
- 已确认的可用基础：ID 入口的压缩、原子写入、原文读取和重复执行去重已通过离线合成 CLI 检查；请求冻结、失败恢复、源版本校验与召回范围过滤已有实现。

以上是合并后发现的问题，不认定每项均由合并操作引入。实施前补充对应失败回归，并保留修复前后证据。

调查阶段合并前相关测试 53/53、合并后召回测试 17/17 通过；两组结果不是同一快照的完整回归。合并后本机缺少新增依赖 `@huggingface/transformers`，构建报 TS2307；先恢复锁文件对应依赖再建立统一基线。沙箱临时目录曾出现 rename EPERM，本机隔离测试正常，不能把该环境失败记为业务缺陷。
