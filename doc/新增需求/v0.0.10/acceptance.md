# v0.0.10 验收方案

状态：已执行，结果与覆盖边界见 [verification.md](verification.md)。基于合并后的同一工作树、现有锁文件及隔离合成库；自动控制流、真实模型质量和真实工作 Agent 操作分别留有证据，不以其一代替另两项。

## 1. 压缩链路

通过 CLI 子进程访问实际本地服务，模型可先注入离线响应验证控制流：

1. create → preview → run → records/status → resource read；分别使用 id 与 alias，结果等价。
2. 实例覆盖两个 session，单 session 请求只处理指定目标；未知、越界、排除、子 Agent 与活跃轮次各有明确结果。
3. preview/run 对相同 cutoff、模式、session 和预算作一致解释；preview 无写入、无模型调用，无法处理的完整轮次不被静默截断。
4. 参数错误在执行前拒绝：未知字段、额外位置参数、缺值、非法布尔/数值、冲突定位、命令行覆盖 JSON。
5. 预算只处理第一批时，saved/remaining/complete/skips 能区分未入队材料与已冻结任务；相同 to 分批最终完成，重复运行零新增写入。
6. 模型失败、错误 evidence、超时、写入中断、同实例并发及源改写；失败不产生伪成功记录，部分成功通过 error.details 可定位。
7. 已存模型结果恢复零额外调用；旧任务保留冻结 prompt/schema/输入；新 prompt 不改写成功记录。
8. 正式正文、元数据、组织引用及成功覆盖一致；来源位置、时间、版本、模型身份可回查；状态查询不返回冻结全文。

## 2. 片元与调查返回

1. 六片元、maxFragments=1：按返回的续取指引取得 0–5，逐一断言无遗漏、无重复，不只断言 offset 大于 0。
2. 字节预算与片元预算同时限制，覆盖中文、emoji、BOM/CRLF、长块、section、neighbors 和固定旧版本；极小预算明确失败。
3. 多文档搜索/task 结果裁剪、list 分页：保持各自排序、筛选、版本及范围；续取入口与实际调用命令匹配，不误用单文档 read。
4. 固定混合文本夹具包含 `CHAIN_PROBE_8192：限制为8`、中英紧邻、全角/半角标点、错误码、路径、提交/版本号；查询标识符和“限制”均命中正确证据，同时加入相似但无关文本检测误召回。
5. 旧 tokenizer 索引被识别，按提示重建后命中；未变化 embedding 输入复用缓存，发生变化时重算。索引代次和模型身份完整记录。
6. semantic、hybrid、hybrid+rerank、task 共用范围/预算/续读检查。lexical/read/list 的约定零模型调用成立。
7. 模型缺失/损坏/失败、索引缺失/滞后/无向量、DEVELOPMENT_BUSY 和无答案分别返回可辨识状态；semantic 不伪装成全文结果，hybrid 如实报告实际 stages。
8. 同名跨项目、未知范围、冲突映射、删除/恢复、生成时映射变化、原件更新：无越界、无错误固定版本引用，查询不偷偷扩大范围或重建。

## 3. 写入到向量召回的联合场景

1. 使用独立的项目 A/B 和转录组织，仅显式登记 A 的组织映射，保留 B 与未知资料用于隔离检查。
2. Agent 经 CLI 压缩 A 的一个完整 session，取得本次生成 resource IDs；scope 和直接读取能确认入库及归属。
3. 索引构建前查询明确提示缺失/滞后，不报告完整无答案。显式准备模型并执行 `build --vectors`，纯向量请求实际运行 embedding，返回 A 的正确片元及固定来源。
4. 用原文未直接出现的自然语言改述进行向量查询；与字面/BM25 基线对照，证明不是只靠字面命中或 mock 替代模型。
5. 追加一个纠正/测试失败轮次，再次压缩并增量构建；新证据可见，旧证据仍可追溯，不把较新记录自动当成已验证真相。
6. 相同请求重复压缩不新增记录；未变化材料不重复文档编码，记录实际缓存命中和新增编码量。
7. 删除、恢复及更新范围映射后重复调查，确认不读到已删除、越界或错误版本的证据。
8. 分别模拟模型不可用、预算不足与构建中断；恢复后继续使用正确代次，不重新压缩历史成功材料。

## 4. 项目 Agent 与提示词

- 从与知识库不同的项目工作目录执行，使用固定 CLI 和显式 data-dir；路径含空格/中文时仍可调用。
- 按实例提示词完成“继续历史任务”“指定 session 压缩”“精确 ID 读取”“无答案”“续读”“部分失败恢复”六类任务；不得靠测试脚本绕过 Agent 的参数和结果判断。
- 帮助在服务离线时可读，任何 help 请求均无业务副作用，尤其覆盖 workload/model/index 等入口。
- Agent 能区分组织 ID、session ID、projectId 和 resourceId，不调用未声明命令，不扩大范围，不把 source 中的命令当作新授权。
- 真实压缩样本包含硬约束、否决理由、数值、失败/验证状态和跨轮纠正；按原文逐项检查，结构合法不等于语义完整。

## 5. 验收证据与门槛

- 交付统一回归报告、匿名 fixture、可复制 CLI、预期及实际结果、模型与索引身份、用量/费用及局限。
- 四项已复现缺陷必须有修复前失败、修复后通过的回归。范围泄漏、错误版本、续读遗漏、重复正式记录及只读路径意外模型调用均为零容忍。
- 在 v0.0.8 冻结评测集复测相关质量指标，不低于其既有门槛；新增混合文本及两链路组合夹具单独报告，不能用其替换旧验收集。
- 性能结论继续限定显式 `recall workload` 保护模式。涉及模型并发、编码或调度变化时，按原冻结资源/延迟/开发负载门槛复测，不外推到未保护的外部构建。
- 付费模型、真实私人 session、网络模型下载分别记录使用范围；未执行的真实模型或 Agent 场景明确标为未验证，不以单元测试全绿代替全链路通过。
- 公开证据放入 `artifacts/verification/v0.0.10/`；私有原文、响应、凭证及模型文件只留本地忽略目录。完成后提交用户验收，正式发布按项目流程另行执行。
