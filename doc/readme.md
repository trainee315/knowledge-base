## 推进方式

参考个人项目中心现有文档流程：

1. 在 `doc/新增需求/v{version}.{publish}.{fix}/readme.md` 中记录目标版本的范围、状态与验收条件。复杂主题按需拆分文档。
2. 讨论期间区分用户已确认要求、设计建议和待定项。建议不能直接视为已确认需求。
3. 明确交付范围和验收条件后，进入实现；实现方案与验证结果按实际进展补充，不提前记录为已完成。
4. 实现与自动验证完成后记录状态，开展用户验收。
5. 实现及验收完成后，将已落地行为归档到 `doc/v{version}.{publish}.{fix}/`，更新当前版本入口及[版本历史](./version-history.md)。
6. 后续需求推进期间冻结已发布版本文档，在新的目标版本目录记录变化。

版本目录沿用 `v{version}.{publish}.{fix}` 约定：version 由项目负责人决定是否增加，publish 对应一次完整功能发布，fix 对应缺陷修复。首期版本已确定为v0.0.1。
